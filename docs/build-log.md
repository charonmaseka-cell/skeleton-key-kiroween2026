## SC-T2b: budget fix and output-aware chunking (1 Nov 2026)
- **Brief imported** verbatim to `docs/reference/scopecheck-build-brief.md`; `.kiro/steering/brief.md` carries the approved amendments (stack, protected scope, evidence/omission rules, uncertainty, match scores as suggestions, accuracy requirements kept, no one-minute promise, 30 October submission start, hooks configured vs run).
- **`NeuronBudget.settle()` fixed.** The old `Math.min(reservation, estimate)` discarded consumption above the reservation. Now the FULL estimate from reported tokens is charged, an overrun is recorded, persisted in the ledger and counted against both caps, and `capReached` blocks every later reservation. One margin (`SAFETY_MARGIN` 1.1) is applied in `charge()` for reservations and settlements alike. The input bound is 2 bytes per prompt token plus 64 template tokens: a CALIBRATED bound (14 live requests measured 4.45 to 5.40 bytes per token, mean 4.73), not a guarantee; characters divided by three is no longer used. Missing or partial usage keeps the reservation; a failed call keeps it. Regression tests cover usage above the reservation, missing usage, an overrun that reaches a cap, and a multi-chunk run that stops after an overrun.
- **Output-aware chunker** (`packages/engine/src/chunk-output.ts`, domain-neutral): sizes requests by the values the schema is expected to return, from block text, structure (rows and continuation lines, headings) and the schema's value kinds. It never reads labels. It repeats the nearest heading as context, supports overlap, keeps an over-budget row alone and flagged, reports oversized blocks, and accounts for every block (`unaccounted` must be empty). The value budget is 14 per request: an ESTIMATE from small samples (42 output tokens per value, 29 to 36 tokens/s, 25 s timeout, 1,500-token cap), not proof that larger requests cannot work; `--values-per-request` overrides it.
- **Frozen plan** `samples/scopecheck-realistic/chunk-plan.json`: rfq 6 chunks, quote-a 8, quote-b 7 (21 requests). A test regenerates it and requires an identical file; the frozen chunker refuses a document whose text hash differs. Label-derived counts are in a separate `diagnostic` section (offline benchmark diagnostic; the chunker and the run never read them), and a test shows the chunks do not change when labels are removed or scrambled. The browser client uses the same chunker (`packages/ui/src/schema-fields.ts`); a test fails if its value kinds drift from the server profiles.
- **Preflight** now compares the expected ACTUAL charge and the PEAK reservation (charged so far plus one worst case) with the caps, instead of the sum of first-attempt worst cases, which reservations replace. Latency forecasts: refused only when the typical-rate forecast passes the timeout; a forecast that passes 90% at the slowest measured rate is a warning.
- **Budget arithmetic for the realistic set** (estimates): about 860 (rfq), 1,040 (quote-a) and 950 (quote-b) neurons expected, so neurons are not the binding limit; the 16-attempt allowance is. 21 first attempts are needed, with no repair.
