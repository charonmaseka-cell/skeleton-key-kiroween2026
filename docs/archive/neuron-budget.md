# Server-side neuron budget (task 5.5, option A)

Status: **implemented offline, not deployed, not enabled.** Production `DAILY_NEURON_BUDGET = "0"` and `DAILY_ADMISSION_CEILING = "0"`: nothing is admitted. The proposed public value is **5,000 estimated neurons per UTC day** (half the free plan's daily allocation), applied only after task 5.5 passes. The free plan is unchanged.

## What the Worker does for every inference attempt (repairs included)
1. Builds the exact messages, then computes the attempt's **reservation**: the worst case for those messages and the profile's whole output allowance (`src/cost.ts`).
2. Asks the Durable Object to **reserve**, in one transaction: admitted only if today's attempts are below `DAILY_ADMISSION_CEILING`, today's charged neurons + this reservation are at most `DAILY_NEURON_BUDGET`, **and no overrun has been recorded today** (see below). A refusal writes nothing and returns `daily_limit` before the model is called. A ledger failure closes the service (`limiter_unavailable`).
3. Calls the model.
4. **Settles**: if the model reported both token counts, the attempt is charged the full estimate from those tokens, **not clipped** to the reservation; a charge above the reservation is flagged as an **overrun** (stored in full, logged, and counted against the day). **A recorded overrun locks the UTC day**: every further reservation, including the repair of the request that overran, is refused (`daily_limit`, logged reason `overrun`) even when nominal budget remains, because the cost bound has been shown wrong for a real call. An answer that was already valid is still returned; the lock ends at 00:00 UTC. If usage is missing or malformed, or the call failed or timed out, the reservation **stands** (consumption unknown). If the Worker dies between reserving and settling, the reservation stands. Nothing is ever refunded below a settled figure.
5. **A settlement the ledger cannot record stops the request.** Settlement is retried once (it is once-only, so a retry cannot double-charge). If it still fails, the request ends with `503 limiter_unavailable` before any repair and without returning claims; the reservation stands. When the reported usage showed an overrun, the log records `knownOverrun: true` and the estimate, so the larger charge is not silently replaced by the smaller reservation while the request carries on. Limit: if the ledger stays unreachable, the overrun cannot be written to it, so the day lock cannot be set; admissions fail closed while it is down, and the log entry is then the only record. Re-check `/health` (unsettled reservations) after any `ledger_unavailable`.

Because every admission checks charged + outstanding reservations against the budget, the day's estimated total stays at or under the budget by construction, **except for overruns**: at most the overruns of calls already admitted when the first one settles (concurrent calls in flight), after which the day is locked.

Ledger rows: UTC day, reserved, charged, state, overrun flag. No document text, no client data. Rows older than 7 days are deleted. `/health` reports today's attempts, charged estimate, unsettled reservations and overruns, and probes the admission path with a refusal that writes nothing.

## Assumptions behind the cost bound (each stated so it can be checked)
| | Assumption | Evidence / what breaks it |
|---|---|---|
| A1 | Rates: Cloudflare's published neuron rates for `@cf/meta/llama-3.3-70b-instruct-fp8-fast`, **26,668 per million input tokens and 204,805 per million output tokens** (from Cloudflare's published Workers AI pricing, 2 Nov 2026). Earlier figures used price-derived rates (26,636 / 204,818, from $0.293 / $2.253 at $0.011 per 1,000 neurons); historical results keep those. A model without a listed rate is never called (`not_configured`). | Two dashboard comparisons: checkpoint 1, 462.81 measured vs 462.76 estimated at the earlier rates (5 attempts); the task 5.5 gated test, a 321.65 increase vs 321.654982 at these rates (4 attempts, 3,414 in / 1,126 out). The two rate sets differ by about 0.03% on that run. If the dashboard diverges, all charges (reservations and settlements) are wrong by the same factor; the 5,000 of 10,000 split is the margin for that. |
| A2 | Margin x1.1 on every reservation and settlement. | Same factor on both, so they are comparable. |
| A3 | Input tokens <= UTF-8 bytes of the messages + 64. | A byte-level BPE token covers at least one byte. The 64 covers the chat template and anything the provider adds (for example from `response_format`). Observed 4.45 to 5.40 bytes per reported prompt token over 14 live requests, small ones included, so additions are small. If the provider added more than 64 tokens, settlement still charges the reported figure and records an overrun. |
| A4 | Output tokens <= the profile's `max_tokens` (1,500 ScopeCheck, 1,200 PackCheck). | Enforced by the provider; never exceeded in the measured runs. A breach would show as an overrun. |
| A5 | One model call per admitted attempt; the usage the model reports is the usage charged. | A call the Worker abandoned at the 25 s timeout may still finish and consume; its usage never reaches the Worker, so its reservation stands (it covers A3 + A4). |
| A6 | All figures are **estimates**. Only the Cloudflare dashboard shows consumption. | Dashboard readings are compared after every live run. |

Bound at the proposed limits (`MAX_BODY_BYTES` 8,192): the largest reservation any accepted request can produce is **630.837** estimated neurons at the published rates (`scopecheck.quote.v1`, 9,921 message bytes + 64, 1,500 output tokens, x1.1, rounded up). `docs/results/task-5-5-reservations.json` (PR #11) records 630.5 under the earlier rates and is kept as written. How many attempts 5,000 admits depends on settlements: the gated test averaged about 88 charged (353.7 / 4, margin included, small payloads), so a figure like "about 57 attempts" is an **estimate from one run of four small requests, not a guarantee**; large chunks and outstanding reservations admit fewer.

## Configuration
- `DAILY_NEURON_BUDGET`: **required**, integer 0 to 10,000 (hard cap = the free daily allocation). Missing or invalid closes the service.
- `DAILY_ADMISSION_CEILING` stays as an attempt backstop (proposed 40 with the budget).
- Production `wrangler.toml`: both 0. `tools/deploy/deploy.ts` passes `DAILY_NEURON_BUDGET:0` explicitly. The staging gate Worker (`wrangler.gate.toml`): 2,000, matching the authorised test cap.

## Whole-run admission (3 Nov 2026; offline, not enabled)
A run (every document of one Analyse) is priced from its chunk plan and held as a whole before anything is sent, or refused up front; once held it cannot be cut off by the budget. Mechanism, assumptions, what it costs in runs per day, and the tests: `docs/live-opening.md` (section "Whole-run admission") and `docs/results/run-admission-simulation.md`. Ledger code: `services/extraction-api/src/admission.ts` (`openRun`, `reserveInRun`, `settleInRun`, `closeRun`); pricing: `src/run-plan.ts`. The per-attempt reservation above is unchanged and still used by any request that does not belong to a run. Inside a run there is no automatic repair and the output is capped at 972 tokens (enforced as `max_tokens`).
